## 背景（已探明的事实）

两个探索代理完成了全面盘点，结论：

1. **路由定义无任何专门讲解**：`"POST /path"` 方法模式语法、`{id}` 路径参数、ServeMux 优先级/冲突 panic/405+Allow 语义、各注册 API（HandleJSONTyped/HandleJSONWithMiddleware/HandleJSONEndpoint/Handle/HandleFunc/HandleSSETyped 共 10+ 个）的选择依据——散落各处或完全无文档。`kit.HandleJSONTyped` 只解码 JSON 体，带路径参数必须用原生 handler + `r.PathValue`，而 `DecodePathRequest` 的存在零提及。
2. **其余用户关心的缺口**（按影响排序）：transport-neutral 的 `security` 包（Subject/Authenticator/RequireRole）没有 README 且索引指向错误的 security/http；独立 `health` 包无 README、两个索引都够不到；手写服务的配置无归属（configuration.md 只讲生成项目）；MICROGEN 讲了生成的 SDK 却没有任何调用代码示例；multipart/分页/文件下载只存在于 transport README、书内不可达；`/debug/routes` 的 JSON 形状与启动路由清单无文档；SSE 无教程无示例；`kit/grpc`、`integrations/zap` 不在索引中。

已核实 `v2/security/security.go` 与 `v2/health/health.go` 的导出面。范围按推荐：**仅文档补全，不新增 examples 代码**（SSE 示例记为后续工作）。
